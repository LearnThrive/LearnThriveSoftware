# Voice mode benchmark

Generated by `apps/web/scripts/voice-bench.mjs` (and `services/voice/bench.py`) on 2026-10-26 (plan19 section 5.4). Raw numbers: `docs/benchmarks/voice-engines.json`, `docs/benchmarks/voice-pipeline.json`.

> **Every recording here is synthetic.** The phrases were spoken by text-to-speech voices (never a child, never a real recording), so recognition scores are **optimistic**: a child's voice, a classroom's noise and an unfamiliar accent are harder. The owner's own recordings of real phrases, added to `tests/fixtures/assistant/voice-phrases.json` as WAV files, would be better evidence. Nothing here was heard by a person.

## The set

30 phrases of the kind a student says (maths and science vocabulary: x squared, quadratic, denominator, photosynthesis…), each spoken by 7 synthetic voices (kokoro-bf_emma, kokoro-bm_george, piper-en_GB-alba-medium, piper-en_GB-jenny_dioco-medium, piper-en_GB-northern_english_male-medium, sapi-hazel, sapi-zira), once clean and once with white noise added at 15 dB signal-to-noise. Word error rate is computed after folding digits to words ("5x" and "five x" are the same) and punctuation away. "Terms found" is the share of the maths and science words that were recognised correctly.

## The whole pipeline, end of speech to first audio

The speech sidecar and Ollama (`qwen3.5:9b`, voice-mode prompt) as the site uses them, 6 utterances per configuration after a warm-up. "End of speech" is the moment the recording stops; the clock stops when the first clip of speech has been synthesised (the browser then starts playing it, a few milliseconds). The model's first spoken chunk is what the page speaks first: its first complete sentence, or that sentence cut at a natural pause when it is longer than 64 characters (speech.ts, `speechChunksPartial`). The hop through the Next route adds a few milliseconds and is not included.

## Decision

- **Recognition: Parakeet CTC 1.1B (`parakeet-ctc-1.1b.q8_0.gguf`), the local default.** 1.6% clean and 3% noisy word error, 94.2% of the maths and science terms found, 29 ms median a clip (p95 56), real-time factor 0.011, 5.68 s to load, 1655 MB of VRAM while it ran. The best whisper row here is `small.en` (cuda) at 1.8% / 3.1% and 119 ms. The runtime reported confidence per words.
- **Rollback: `VOICE_STT_ENGINE=whisper`** restores the pre-migration faster-whisper path (`small.en` on cuda, 119 ms). The sidecar also falls back to it by itself when the runtime or the GGUF is missing, and names the reason in `/health`.
- **Speech output: Kokoro 82M `bf_emma`, the local default.** Its first chunk takes 750 ms against Piper's 72 ms (10.4x slower), paid once per spoken segment; later chunks queue behind playback, so the voice is rarely the limit. `VOICE_TTS_ENGINE=piper` restores Piper, and the browser's `speechSynthesis` remains the automatic fallback when the sidecar is unreachable.
- Push-to-talk only. Hands-free voice-activity detection was not built: it needs a measured false-trigger rate in a real room, and the first version should not listen when nobody pressed anything.

### What would change it

- A real child's voice and a real room: rerun with recordings. If word error rate is much worse than here, the next step is `medium.en` on the GPU (on the CPU it took 4.7 s a clip; it was not measured on the GPU here).
- A different machine: the CPU timings are for this CPU. A slower school-lab or hosted machine needs the numbers again.
- A hosted speech provider (a processor for a child's voice) is a plan19 section 6 decision; this report does not cover one.
- Running the language model and the recogniser on one 8 GB GPU is possible (see the VRAM column: the whole GPU, desktop included, peaked at 7.8 of 8 GB) but leaves little room, so a second large program on the GPU would push the language model into system memory and slow it. CPU recognition (`VOICE_STT_DEVICE=cpu`) avoids the contest at a cost in accuracy, and puts the speech output's synthesis back in competition with the model.

## Reproduce

```bash
cd services/voice && uv sync
node ../../scripts/parakeet-local.mjs          # verifies and extracts the NeMo-Speech.cpp runtime and the Parakeet GGUF
uv run python -m piper.download_voices --download-dir models en_GB-alba-medium en_GB-jenny_dioco-medium en_GB-northern_english_male-medium
cd ../../apps/web && npm run voice:bench -- --stt parakeet/cuda,small.en/cuda
```

Kokoro needs `kokoro-v1.0.onnx` and `voices-v1.0.bin` from the kokoro-onnx release in `services/voice/models`; the CUDA runs need `uv pip install nvidia-cublas-cu12 nvidia-cudnn-cu12`. Models are downloaded from their publishers' hosts and are not committed. `--stt parakeet/cuda` drives the shipped adapter (it spawns the runtime itself); `base.en/cpu` drives the whisper path.
