## How it was measured

- Settings: context 8192 tokens, at most 500 output tokens, temperature 0.3, thinking turned off where the model supports it, the real Study Buddy system prompt, one request at a time, the model loaded before timing starts (the first, load, request is not counted). Time to first token and total time are taken from the provider code the site itself uses.
- **Quality** is a deterministic rubric (regular expressions over the answer; `tests/fixtures/assistant/eval.json`): maths KS2 to A Level and 11+, English, Science, maths notation (LaTeX present) and hints-first behaviour. The real system prompt is hints-first, so the answer-checking questions add that the pupil has finished and wants to check the final answer; the hints, coursework, injection and welfare prompts are sent as written. **No LLM judge was used**, so a correct answer worded unusually can score zero: it ranks models against each other, it does not grade a pupil.
- **Safety pass rate** is the model's own behaviour on coursework requests, prompt-injection attempts, off-topic and adult requests and welfare disclosures, with the rules switched off ("model alone"); "with the rules" counts a prompt as held if the input rules would have turned it away or the output guard would have stopped the answer. The model is the second line, not the first.
- **Vision** uses 5 pictures of typed text made with ffmpeg: it is NOT handwriting, so it measures reading, not a child's scrawl. There is no handwriting set.
- Memory is Ollama's own report (`/api/ps`) after the run: VRAM plus any part in system RAM. Budget: weights plus context cache under about 7 GB of the 8 GB GPU, so the desktop and the speech models have headroom.

## Decision (set by the script's rule, then read by a person)

- **Default text model: `qwen3.5:9b`**: the highest quality score among the models that fit the GPU budget and hold at least 90% of the safety prompts on their own (71%), faster first token breaking a tie (p50 0.31 s).
- **Default vision model: `qwen3.5:9b`**: the most pictures read among the models that fit the budget (3 of 5).
- Context size: 8192 tokens, at most 500 output tokens a turn, temperature 0.3, thinking off. These are what the numbers above were measured at.

### What would change it

- A different GPU, or a model quantised differently, changes which models fit and how fast they are; rerun the script.
- The rubric is regular expressions, so small differences in quality score (a few points) are noise, not a ranking. A real marking panel on real, approved material would be better evidence than this synthetic set.
- First-token time grows with the length of the conversation and with a photo or PDF attached; these numbers are for a short question.
- The voice latency target (plan19 section 5.4) needs the first model token under 1.0 s; compare the p50 and p95 above with that.
