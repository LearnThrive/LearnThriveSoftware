# Plan 12 — Anti-generic visual audit (Task 15)

## Method and its honest limit

This session has no browser/screenshot tool (see `PLAN12_BASELINE.md`). Plan12.md's own instruction for this task is "review screenshots for homepage, Subjects, all subject pages, About, Book, Safeguarding, FAQ and Contact" — that step could not be done as written. Instead, four parallel review agents read every route's actual `.tsx`/`.module.css`/relevant `globals.css` source and answered the plan's ten anti-generic questions structurally, citing the file/line/selector behind each verdict rather than a rendered impression. Every "concern" verdict below was then re-checked by hand against the live file before any fix was made, and two of the audit's proposed "concerns" were downgraded after that re-check (see "Reviewed, not fixed" below) — reading a shared `border-radius` value across two elements is not the same as two elements actually reading as duplicate cards, and the source alone can't always settle that; where it couldn't, the verdict is `cannot-tell-structurally`, not a guess.

Routes covered: `/`, `/subjects`, `/maths-tuition`, `/english-tuition`, `/science-tuition`, `/11-plus-tuition`, `/about`, `/book`, `/safeguarding`, `/faq`, `/contact`.

## Fixes applied

1. **Subject landing pages (all four) — coverage cards no longer duplicate the support grid's card recipe.** `.subject-benefit-grid .feature-card` (support section) and `.subject-pathway-card` (coverage section) shared the exact same white background + bordered + coloured-top-accent + lift-shadow recipe, one directly under the other, on every one of the four subject routes. Removed `box-shadow: var(--shadow-sm)` from `.subject-pathway-card` (`globals.css`) — the coverage cards now read as flatter waypoints along the section's own drawn path/underline/node motif rather than a second identical card grid. One change, benefits `/maths-tuition`, `/english-tuition`, `/science-tuition` and `/11-plus-tuition` alike.

2. **`/11-plus-tuition` — the coverage section's drawn line now matches its own hero's "route" language instead of maths's "curve".** The route's hero (`RouteMilestones`) already draws a dashed path; the coverage section underneath reused `PathTrack`/`Milestone` from `/maths-tuition` verbatim, solid line and all — so half of the route's one visual idea was a straight copy, not something of its own. `PathTrack` (`SubjectWorld.tsx`) now takes a `dashed` prop, applied for `kind === "11-plus"` (both on the dedicated landing page and on `/subjects`' `ElevenPlusMotif`). The dash only goes on the *static* guide line, not the scroll-drawn one — Framer Motion's `pathLength` style computes its own `stroke-dasharray`/`stroke-dashoffset` on the drawn line every frame to animate the reveal, which silently overwrote a static `strokeDasharray` prop passed alongside it (a real bug caught by the first version of this fix's own test, not a pre-existing one — see `SubjectWorld.tsx`'s `PathTrack` comment).

3. **`/book` — the sidebar no longer competes with the form as a third card.** The route already has two other bordered/rounded surfaces (`.contact-mini-card` in the hero, and `.enquiry-form` itself, already given corner-bracket framing in Task 12 specifically so it wouldn't need a second heavy box). `.booking-sidebar` still had its own full lift-shadow on top of its border-radius and navy background. Dropped the `box-shadow` only — it keeps its green top-accent border and navy panel (a real echo of the hero above it), just without reading as a competing floating card.

Covered by new tests: `subject-worlds.spec.ts`'s "subject coverage card composition (task 15)" block (the dashed vs. solid guide line, the missing lift-shadow) plus the existing full regression suite (marketing-motion/view-transitions/subjects-universe/subject-worlds/enquiry-form/legal-page-motion — 190+ tests) re-run unmodified and green after these changes.

Profiled `/maths-tuition`, `/11-plus-tuition`, `/book` and `/subjects` at desktop 1440x900 (`artifacts/motion-profile/plan12-task15.json`): LCP 148-228ms, CLS 0, no console/page/broken-image errors. `/subjects`' scrollDown dropped-frame estimate read 17.86% in that run; an isolated re-profile (`plan12-task15-subjects-isolated.json`) showed 4.5-13% across its own three runs (median 7.94%) — this route's scroll-cost figure is inherently noisy (Task 14's own profiling run of the same, unmodified route read 4.95%), and neither change here (a `box-shadow` removal, which reduces paint work if anything, and a static SVG `stroke-dasharray` attribute set once, not per frame) plausibly explains a real regression. Treated as environment variance, not a fix-worthy finding.

## Reviewed, not fixed

- **Homepage `.howImage` / `.levelRow`, and `/subjects`' `.subjectImage`**, flagged by the audit for sharing a `border-radius` value with the page's genuine card grids. Re-checked directly: none of these three actually carry the lift-shadow/hover-elevate treatment the real cards (`.whyCard`, `.subjectCard`, `.levelCard`) use — `.howImage`/`.subjectImage` are plain bordered photo frames with no shadow or hover state at all, and `.levelRow` has its own distinct hover language (a sideways slide, not a lift) and a different internal layout (a horizontal row, not a stacked card). A shared corner radius alone doesn't make these "every surface rounded into a card" in the sense the question is actually probing; left unchanged.
- **`/science-tuition`'s coverage motion ("is motion merely decorative?")** — `ScienceNodes` drifts three fixed dots near the section heading rather than tying each dot to one of the four coverage cards the way `Milestone` does for maths/11-plus. `SubjectWorld.tsx`'s own top-of-file comment already documents this as a deliberate, reasoned restraint (three nodes echoing the hero's connected-node motif, not an attempt to force a literal per-card mechanism onto content it doesn't naturally fit) rather than an oversight. Re-tying it to specific cards would mean either a fixed count mismatch (3 nodes vs. 4 cards) or measuring real card positions in JS — a bigger, riskier change for a nuance this task's own mandate ("fix obvious repetition") doesn't call for. Left as already-reasoned restraint, not repetition.
- **`/english-tuition`'s coverage-card numbering weight** — a minor suggested tweak (give the coverage card's number a different visual weight than the support card's icon) on a route whose coverage section already has its own distinct mechanism (`AnimatedUnderline`, unlike every other subject). Fix (1) above already reduces the two grids' visual similarity sitewide; this additional per-subject nuance was judged not worth a second change on top of that.
- **Three `cannot-tell-structurally` verdicts** (About/Safeguarding/FAQ/Contact's "does it still unmistakably feel like LearnThrive?") — every route shares the same brand tokens and primitives, which is as far as source-reading can confirm; the actual felt impression needs a rendered view, honestly out of reach this session.
